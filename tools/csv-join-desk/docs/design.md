# Design references

The operation is established, not novel. This work provides a bounded local workflow with explicit preflight and row provenance.

- [RFC 4180, section 2](https://www.rfc-editor.org/rfc/rfc4180#section-2): comma-separated fields, header consistency, doubled quotes and embedded newlines. Input uses Python's strict CSV dialect with explicit UTF-8 decoding rather than claiming full RFC conformance; output uses the standard writer and CRLF records.
- [Python CSV documentation](https://docs.python.org/3/library/csv.html): reader/writer behavior and newline handling. Files are parsed with `newline=''`; no automatic numeric conversion.
- [DuckDB FROM and JOIN documentation](https://duckdb.org/docs/current/sql/query_syntax/from): existing inner, left, full outer and composite equi-join functionality. DuckDB is an existing general-purpose alternative. This application's in-memory index produces the same bag multiplicity model, while supplying explicit source ordinals, missing-key semantics, and preflight limits.
- [OurAirports official data repository](https://github.com/davidmegginson/ourairports-data/tree/b529623d2a0b09a9be78d37fc7a7a5e1e16e3451): primary source for the acquired tables, pinned license, and README. `airports.iso_country` joins `countries.code`; actual headers and original field values are retained. [Data documentation](https://ourairports.com/data/) and [data dictionary](https://ourairports.com/help/data-dictionary.html) returned HTTP 500 during this build; the checked-in official source files and license remained accessible. The pinned repository's `LICENSE` is retained verbatim with its hash and URL. [datasets/airport-codes](https://github.com/datasets/airport-codes) independently documents the OurAirports country code and the important distinction between literal `NA` (Namibia) and a missing field; it was inspected as an existing data preparation implementation, not used as our input.

The join engine indexes tuples, not concatenated strings, so composite values containing delimiters cannot collide. Empty key components are excluded from both indexes and retained in missing-record accounting. Cardinality and conservative UTF-8 CSV size are derived from group multiplicity before building pairs. No input row is silently discarded. Full outer output includes each unmatched record exactly once; a matched record may occur repeatedly according to multiplicity.

The independent verifier deliberately uses nested loops and separately reconstructs expected pairs, values and accounting. It shares only the documented format and standard-library CSV parser; browser verification uses a separate JavaScript parser as an additional parsing check. Hashes provide integrity checks, not cryptographic signatures or authenticity claims.
