# Reference model and prior work

This project does not claim a novel dependency-analysis algorithm. It packages static formula evidence, conservative coverage labels, and portable review notes into a local workflow.

Primary sources inspected during implementation:

- [Microsoft Open XML CellFormula documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.cellformula?view=openxml-3.0.1): the cell `f` element distinguishes normal, shared, array, and data-table formulas. Shared followers may omit text; this explorer retains original attributes and translates followers from the shared master. Array/data-table formulas are marked unresolved, including when some static references can be extracted.
- [openpyxl formula parsing documentation](https://openpyxl.readthedocs.io/en/stable/formula.html): tokenization distinguishes range operands from strings and functions, but is not a full formula evaluator or correctness checker. The implementation uses its tokenizer and shared-formula translator, not its workbook value reader. Original XML literals and cached values remain separate.
- [LibreOffice Trace Precedents](https://help.libreoffice.org/latest/en-US/text/scalc/01/06030100.html): an existing spreadsheet viewer already supports precedent tracing. This project's additional scope is a source-hashed annotation and portable evidence workflow.
- [LibreOffice XFormulaQuery API](https://api.libreoffice.org/docs/idl/ref/interfacecom_1_1sun_1_1star_1_1sheet_1_1XFormulaQuery.html): `queryPrecedents(False)` supplies the independent spreadsheet application's direct precedent inspection. Ten cross-sheet query mismatches are retained, rather than hidden. The stronger edge oracle comes from [XFormulaTokens](https://api.libreoffice.org/docs/idl/ref/interfacecom_1_1sun_1_1star_1_1sheet_1_1XFormulaTokens.html), expanding Calc's SingleReference/ComplexReference structures with [ReferenceFlags](https://api.libreoffice.org/docs/idl/ref/namespacecom_1_1sun_1_1star_1_1sheet_1_1ReferenceFlags.html). Neither uses the explorer's tokenizer. This is API-based inspection, not a visual comparison of Calc's arrows.

## Implementation boundaries

The server reads the original XLSX ZIP in memory, using defused XML parsing. It reads workbook relationships, sheet cells, shared strings, raw `f` text/attributes and `v` cached results. It never opens hyperlinks, recalculates cells, executes macros, or rewrites the workbook. No dependencies are fetched during inspection. The only network dependency after setup is the loopback HTTP connection between browser and local Python process.

Edges point **formula cell → potential precedent**. Every edge carries its formula and originating reference token. The graph reverses those edges for dependents. A finite allowlist of ordinary functions is explicit in `engine.py`; unfamiliar functions are marked unresolved, while recognizable A1 operands still produce partial evidence. IF/CHOOSE/INDEX/lookup ranges conservatively include potential referenced inputs, regardless of branch choice. We do not resolve which branch or lookup result actually executes. Names (including valid defined names), structured references, external workbooks, 3D references, whole-column/row references, dynamic reference functions, spill syntax, array formulas, and data tables are unresolved. Defined names are retained in JSON for inspection, not expanded.

Supported references include same-sheet and quoted/unquoted cross-sheet A1 addresses, `$A$1`, `$A1`, `A$1`, bounded rectangular ranges, and case-insensitive sheet matching. Blank referenced cells are navigable and remain explicit endpoints even when absent from XML. Shared formulas are expanded with openpyxl's A1 translation; unresolved masters remain unsupported. Strings that look like references are not extracted.

A formula is `supported` only when all its parsed reference forms and function names fall within this subset. `partial` means some static edges are retained and issues remain; `unsupported` means issues remain without extracted edges. These labels concern dependencies only. They are not syntax validation, arithmetic checks, or evidence that a formula is correct.

Every trace is conservatively labeled incomplete if **any** formula in the workbook is unresolved, because unknown incoming edges and array output regions can affect otherwise disconnected queries. Limits also mark the trace incomplete. Cycle back edges are detected by iterative depth-first search in the displayed direction; direct-only mode can detect self-loops but does not search outside the direct neighborhood. Cycle presence does not imply that a particular branch executes.

The browser stores only source identity, selection, and notes in localStorage. Reload and imported project files require reconnection of matching source bytes. Analysis from an imported JSON file is not trusted; the workbook is parsed again. Offline HTML is an escaped, script-free report with all stored cells, extracted edges, notes, source identity, and a selected precedent trace. It contains full JSON as text, and no workbook bytes. All original source bytes remain with the user; preserve them alongside the project JSON.
